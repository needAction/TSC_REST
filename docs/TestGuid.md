# 두 PC 온라인 플레이 검사 가이드

> 문서 대조일: **2026-10-26**. 현재 코드·설정을 기준으로 설명을 점검했습니다. 본문의 과거 검사 수치·실행 기록은 해당 날짜의 결과입니다. [현재 상태·문서 검토 범위](문서_현행화_점검표.md)를 함께 확인합니다.

## 1. 준비와 주소

두 PC에 같은 클라이언트 빌드 결과 전체를 복사합니다. 기존 stable 폴더를 사용하며 실행 파일만 복사하지 않습니다. Development Build는 testBuild, 일반 빌드는 stableBuild 설정을 읽습니다. Join에는 주소 입력창이 없습니다.

현재 설정은 에디터 `http://192.168.1.34:3001`, 개발 빌드 `http://192.168.1.34:3001`, 일반 빌드 `http://32.236.55.218:3000`입니다. 실제 접속 가능성은 서버 실행·공개 포트·방화벽으로 별도 확인합니다. LAN 환경의 localhost는 그 PC 자신이므로 두 PC가 공통으로 도달하는 서버 주소를 설정합니다.

## 2. 순서와 통과 기준

| 단계 | 조작 | 확인 |
|---|---|---|
| 서버 | 배포 후 /health 조회 | status=ok. 게임 전체 통과와 구분 |
| 첫 PC | Start_UI 탈출하기 | 참가 A·WaitingRoom_UI 한 개·아직 조작 불가 |
| 둘째 PC | Start_UI 탈출하기 | B 배정·두 명 확인 시 WaitingRoom_UI 생성 생략 |
| 씬 준비 | 각자 방·플레이어 준비 | 양쪽 ready와 서버 Playing 후 조작 허용 |
| 1번 문제 | B 정답 제출 | 오답은 정상 오답, 정답이면 B 문·다음 방 허가 |
| 상대 문 | A 문 확인 | A 다음 방도 해금. ROOM.ID와 RoomNo 구분 |
| 방 왕복 | 열린 문을 왕복 | 이전 방 유지·3초 배경음 전환·프로브 수신 |
| 손 | 걷기·정지·벽·UI 잠금 | Walk/Idle 전환과 조작 복구 |
| 마지막 한 명 | 7번 자기 정답 제출 | 정답이지만 상대 완료 대기 |
| 마지막 두 명 | 상대도 7번 정답 | 문 열기·통과 없이 각자 영상 시작 |
| 결과 | 영상 완주 | Result_UI 탈출 시간·확인 종료 |

영상을 같은 프레임에 시작하거나 결과 시간을 서버에 영구 저장하는 기능은 없습니다. 생존은 3초, 일반 플레이 상태 조회는 5초, 마지막 완료 대기는 1초 기준입니다.

## 3. 음성은 별도로 확인

두 참가자의 마이크·출력 장치·권한·Vivox 연결과 실제 양방향 청취를 검사합니다. 게임 Playing이 음성 청취 성공을 뜻하지 않습니다. Start_UI·대기 프리팹에 과거 세션 테스트 화면의 상태 라벨이 모두 있다고 가정하지 말고 음성 진단과 실제 소리로 확인합니다.

## 4. 종료·만료·실패

정상 leave는 토큰과 자리를 반환합니다. 게임/프로세스 강제 종료는 heartbeat 만료로 자리를 회수합니다. 결과 확인 버튼의 현재 경로는 앱 종료이며 별도 leave·음성 종료 완료 대기를 보장하지 않습니다. 모든 참가자가 나간 뒤 새 입장에 진행이 초기화됩니다. 한 사람만 나가면 남은 ready·진행은 유지됩니다.

대기 중 서버 종료, 빠른 중복 입장, 준비 중 실패, 재시작 뒤 이전 토큰을 검사합니다. 신분·진행 자동 복구는 없습니다.

## 5. 로그와 기록

```powershell
ssh escape-cloud "docker logs --follow --tail 100 --timestamps escape-server-cloud"
```

클라이언트 Player.log와 서버 requestId·role·roomNo·판정·해금 목록을 함께 기록합니다. 토큰·정답 원문을 공유하지 않습니다. 검사 결과는 날짜·서버 버전/이미지·클라이언트 빌드·환경·통과/실패/미실행·재현 순서로 남깁니다.

[로그 설명](http-access-logging.md), [배포](ec2-deployment-guide.md), [정답·문](room-api-and-protobuf.md), [문서 현행화 범위](문서_현행화_점검표.md)를 봅니다. 이 문서는 현재 절차이며 이번 작성에서 두 PC·클라우드·음성 검사를 실행했다는 결과표가 아닙니다.
