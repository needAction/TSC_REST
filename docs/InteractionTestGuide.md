# 데이터 기반 상호작용 테스트 가이드

기준: 2026-10-20. 아래 1~6절은 첫 Closeup 단위의 기록입니다. **정답 UI·API 연결 검사**는 추가한 [정답 입력 API 연결 가이드](AnswerApiConnection.md)를 따릅니다. 문 개폐·다음 방 이동은 후속 범위입니다.

데이터를 수정하는 방법은 [기획자용 적용 가이드](DesignerDataTableGuide.md), 코드 역할은 [구현 설명](DataDrivenInteraction.md)을 참고합니다.

## 1. 준비

1. Unity 6000.2.8f1에서 프로젝트를 열고 컴파일이 끝날 때까지 기다립니다. Console의 빨간 오류를 먼저 해결합니다.
2. Play를 끈 상태에서 `Tools → Game → Rebuild Content References`를 실행합니다. `Tools → CSV → 검사기`에서 현재 데이터를 검사합니다.
3. 로컬 확인 시 `Assets/StreamingAssets/Configuration/connection.json`의 editor 환경 `autoConnect=false`를 사용합니다. 개인 설정을 바꿨다면 검사 후 원래 값으로 복원합니다.
4. 첫 검사는 **A**로 합니다. 기존 B의 R01_LEDPanelPoint 미배치는 별도 콘텐츠 준비 사항입니다. 기능 검사 때문에 CSV의 Active를 임의로 바꾸지 않습니다.

현재 비활성 참조 경고 39개는 원래 비활성 콘텐츠를 가리키는 경고입니다. 이 수를 그대로 허용해 모든 새 경고를 무시하는 방식으로 검사하지 않습니다. 새로운 경고/오류는 이전 결과와 비교합니다.

## 2. 자동 검사

### Unity 물리와 표현 자원

Play 종료 상태에서 **Tools → Game → 데이터 기반 상호작용 검사**을 실행합니다. 임시 씬을 만들고 닫으며 원본 씬·프리팹·CSV를 저장하지 않습니다.

Console의 `[상호작용] Unity 검사 21개 통과`가 완료 로그입니다. 예외가 나오거나 완료 로그가 없으면 통과로 보지 않습니다.

검사 내용:

- PREFAB 13005의 실제 기능 선언으로 스크립트 자동 구성 및 앵커 데이터 주입.
- 정수 mm 거리, 자기 몸 제외, 벽 뒤 클릭 차단, Trigger 제외, 대상 비활성화.
- 데이터 색으로 강조하고 이전 Renderer PropertyBlock 복원.
- Closeup RenderTexture 생성, 게임 컴포넌트 미복제, 카메라 레이어 격리와 원상복구.
- 패널 표시/숨김, UI 잠금으로 이동·시점 조작 차단, 닫을 때 잠금 해제.
- 대상 제거 후 안전한 가용성 판단.

### 순수 로직 회귀 검사

프로젝트 루트 터미널에서 실행합니다. .NET 8 SDK가 필요하며 패키지 복원 환경도 준비합니다.

```powershell
dotnet run --project Tools/CsvValidation.Tests -- .
dotnet run --project Tools/PlayerSpawn.Tests -- .
```

현재 공통 검사는 총 234개(상호작용/Closeup 33개 포함), 플레이어 검사는 72개입니다. 기능 ID 오류·중복·의존 관계·정수 단위·중복 열기/닫기·비활성 대상·Dispose를 확인합니다. 데이터 변경으로 원래 검사 전제가 바뀌면 원인을 검토하고 기대값을 수정해야 합니다. 숫자만 맞추기 위해 검사를 삭제하지 않습니다.

서버 프로젝트 루트에서는 다음을 실행합니다. PowerShell에서 npm.ps1 정책 오류를 피하려면 `npm.cmd`를 사용합니다.

```powershell
npm.cmd test
npm.cmd run csv:validate
```

서버는 현재 157개 테스트입니다. 단위 검사 성공은 실제 Unity 마우스 조작·새 빌드 확인을 대신하지 않습니다.

## 3. 실제 좌클릭과 Closeup 검사

### 임시 대상 생성

1. Join 씬에서 Play를 누르고 **클라이언트 테스트 A**로 입장합니다.
2. Ingame의 방과 플레이어 생성이 끝나면 **Tools → Game → 클로즈업 테스트 대상 생성**을 한 번 실행합니다.
3. 카메라 앞 약 1.25m 위치에 임시 큐브가 생깁니다. 실제 데이터의 PREFAB 13005 기능 조합을 읽되 테스트 모델만 큐브를 사용합니다. CSV·방 프리팹·정답 상태는 바꾸지 않습니다.
4. Game 화면을 클릭해 커서를 잡습니다. 커서 복귀용 첫 클릭은 대상을 작동시키지 않으므로 시선을 맞춘 뒤 다시 좌클릭합니다.

기존 R01 문은 CloseUpUI 선언이 없으며 2030 다이얼은 비활성입니다. 따라서 원래 방만 보고 Closeup 실패라고 판단하지 않습니다. 임시 큐브의 기능 선언을 확인한 뒤 실제 콘텐츠의 모델/앵커/Components를 연결하는 순서입니다.

### 통과 기준

| 순서 | 조작 | 기대 결과 |
|---|---|---|
| 1 | WASD와 마우스로 큐브를 화면 중앙에 맞춤 | 일반 이동·시점 회전이 되고 대상이 표의 색으로 강조됨 |
| 2 | 약 2m 밖으로 이동하거나 시선을 돌림 | 강조와 살펴보기 안내가 사라짐. 먼 거리 클릭으로 열리지 않음 |
| 3 | 범위 안에서 중앙 큐브 좌클릭 | Closeup 패널과 모델 미리보기가 한 번 열림 |
| 4 | 열린 상태에서 WASD·마우스 움직임 | 플레이어 이동/시점이 멈추고 UI 커서가 표시됨 |
| 5 | UI 빈 영역/모델 미리보기 좌클릭 | 뒤쪽 월드에 클릭이 전달되거나 중복 패널이 생기지 않음 |
| 6 | 돌아가기 버튼 좌클릭 | 패널과 미리보기가 닫힘 |
| 7 | 게임 화면 클릭 후 WASD·마우스 | 커서를 다시 잡고 일반 조작 복귀. 재획득 클릭으로 즉시 패널이 다시 열리지 않음 |
| 8 | 다시 열고 Esc | 돌아가기와 동일하게 닫힘. Esc는 UI 취소 보조 기능임 |
| 9 | 열기/닫기 5회 반복 | 중복 Canvas/Camera/미리보기 잔존·붉은 오류가 없음 |
| 10 | 패널을 연 상태에서 Play 종료 | 커서가 에디터에서 정상 사용되고 예외가 없음 |

기존 임시 큐브는 PUZZLE이 연결되지 않은 미리보기 대상이라 오른쪽에 데이터 연결 안내만 표시합니다. 실제 다이얼/정답 입력 UI는 새 정답 UI 검사 메뉴로 확인합니다.

## 4. 실패·수명 검사

테스트 전용 대상에서만 수행합니다. Play 중 수정은 프리팹/씬에 Apply 또는 저장하지 않습니다.

| 조작 | 기대 결과 | 이상 시 확인 |
|---|---|---|
| 대상 앞에 Collider가 있는 임시 Cube 벽 배치 | 벽 너머 대상을 클릭할 수 없음 | InteractionTargetFinder의 첫 표면 판정 |
| 패널 열린 상태에서 임시 대상 비활성화/삭제 | 다음 갱신에 패널이 닫히고 UI 잠금 해제 | WorldInteractionTarget.IsAvailable / CloseupController.Refresh |
| 패널 열린 상태에서 LocalPlayer 비활성화 | 패널·강조가 정리되고 입력 중단 | PlayerInteractionDriver.OnDisable / PlayerPointerDriver.OnDisable |
| 다시 활성화 후 화면 클릭 | 기존 잠금이 남지 않고 조작 재개 | PlayerControlState 토큰 해제, 커서 재획득 |
| Alt+Tab 후 복귀 | 포커스 잃은 동안 시점이 튀지 않음. 복귀 후 화면 클릭으로 커서 획득 | PlayerPointerDriver 포커스·입력 초기화 |

Hierarchy에서 InteractionCanvas는 플레이어 상호작용 수명 동안 하나일 수 있습니다. CloseupCamera와 CloseupVisualPreview는 패널이 열릴 때만 존재해야 합니다. Play 중 Destroy는 프레임 끝에 반영되므로 닫은 직후 한 프레임은 기다립니다.

## 5. 로컬·서버·빌드 데이터 경로 검사

1. 먼저 로컬 A에서 위 항목을 통과시킵니다.
2. 서버용 `data/PREFAB.csv`에도 Components 헤더와 올바른 기능 참조가 있는지 확인합니다. 현재 서버/클라이언트의 기존 모델 경로 차이는 이번 기능에서 일괄 동기화하지 않았으므로 서버 번들 모드는 별도로 경로를 확인해야 합니다.
3. 서버 CSV 검증·재시작 후 Join의 서버 접속 모드로 새로 입장합니다. 이미 로드한 세션에 파일 변경이 자동 반영된다고 가정하지 않습니다.
4. Development Build와 다른 PC에서 확인할 때는 현재 config 주소·서버 이미지·클라이언트 빌드를 함께 갱신합니다. Editor 전용 임시 대상 메뉴는 빌드에 없습니다. 빌드 수동 검사는 실제 모델·Collider·활성 ANCHOR_INTERACT·Components가 준비된 콘텐츠로 합니다.

빌드 테스트 결과는 “실제 대상 선택·패널 표시·조작 잠금·복귀”를 별도로 기록합니다. 에디터 자동 검사나 이전 빌드의 결과로 새 빌드의 통과를 대신하지 않습니다.

Closeup 단위 이후 정답 입력 UI/API 연결을 추가했습니다. 해당 단위를 통과시킨 뒤 문 개폐·실제 다음 방 연결을 진행합니다.

## 정답 입력 단위 검사 추가

[정답 입력 API 연결 가이드](AnswerApiConnection.md)에 독립 로컬 B UI 검사, 데이터 폴더 선택 검사, 실제 C#·TypeScript Protobuf 왕복 검사를 추가했습니다. 기존 '정답 UI 후속' 표기는 첫 Closeup 단위의 범위입니다. 현재 로컬 CSV는 작성 중인 PREFAB 13079·13080·13081 참조 오류가 있으므로 전체 데이터 통과와 분리 검사 통과를 구분합니다.
